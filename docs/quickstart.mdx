# Quick start

Choose an entry point:

- **No provider, no database:** [recorded behavioural walkthrough](behavioural-demo.md)
  with Node.js 20+, `npm ci` and `npm run demo`. This is harness verification.
- **Synthetic conversations:** [configure the conversation runner](conversational-testing.md)
  with your own simulator and judge provider.
- **Conversational RAG:** [attach independent references and retrieval evidence](advanced-evaluation.md).
- **RAG:** [configure semantic evaluation](rag-evaluation.md) with reference data and your own judge.
- **Persistent REST API:** use the Docker instructions below.

See [choose your test](choose-your-test.md) for the capability and CI differences.
Scripted entry points are disabled; historical examples are not launch instructions.
RAG checks and adaptive synthetic-user conversations are included without a
Studio subscription. Live model calls use your own provider and may cost money.
HTTP is the agent connection, not a limit to endpoint testing. RAG checks need
retrieval evidence and independent references, not just answer text.
For published GitHub downloads see the [release guide](release-candidate.md).

## Docker API requirements

- Docker Engine
- Docker Compose v2
- Port 5000, or set `HUMANLY_PORT` to another port

```bash
git clone https://github.com/somnath-biswas-github/humanly.git
cd humanly
cp .env.example .env
```

Set `HUMANLY_API_KEY` in `.env` to a long random value:

```bash
openssl rand -hex 32
```

Then start the stack:

```bash
docker compose up --build
```

The app retries PostgreSQL while it starts, applies ordered migrations, and only
then begins serving requests.

```bash
curl http://localhost:5000/health
```

A ready instance returns HTTP 200 with `"ready": true`.

No model key or Studio account is required for server startup or the
[first smoke test](guides/first-test-run.mdx). That test checks connectivity and
non-empty text only. Conversational and semantic RAG judging need provider configuration.
