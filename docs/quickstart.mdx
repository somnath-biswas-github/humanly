# Quick start

Choose an entry point:

- **No provider, no database:** [evaluate fixed/faulty workflow evidence](workflow-evaluation.md#quick-start--no-paid-providers)
  with Node.js 20+ and `npm ci`.
- **Scripted or synthetic conversations:** [configure the conversation runner](conversational-testing.md)
  with your own model provider. Both modes use a judge.
- **RAG:** [configure semantic evaluation](rag-evaluation.md) with reference data and your own judge.
- **Persistent REST API:** use the Docker instructions below.

See [choose your test](choose-your-test.md) for the capability and CI differences.

## Requirements

- Docker Engine
- Docker Compose v2
- Port 5000, or set `HUMANLY_PORT` to another port

```bash
git clone https://github.com/somnath-biswas-github/humanly.git
cd humanly
cp .env.example .env
```

Set `HUMANLY_API_KEY` in `.env` to a long random value:

```bash
openssl rand -hex 32
```

Then start the stack:

```bash
docker compose up --build
```

The app retries PostgreSQL while it starts, applies ordered migrations, and only
then begins serving requests.

```bash
curl http://localhost:5000/health
```

A ready instance returns HTTP 200 with `"ready": true`.

No model key or Studio account is required for server startup or the
[first smoke test](guides/first-test-run.mdx). That test checks connectivity and
non-empty text only. Conversational and semantic RAG judging need provider configuration.
