# AgentConnectors

An AgentConnector stores the endpoint and optional forwarding authentication
for an AI agent.

Humanly sends a POST body with:

```json
{
  "message": "The suite test goal",
  "conversationId": "run_xxx_conversation_1",
  "history": []
}
```

Supported response forms:

```json
{ "response": "..." }
```

Accepted JSON fields, in precedence order: `reply`, `response`, `message`,
`content`, `text`, `answer`, `output`. The first string value is used and trimmed.
An empty/whitespace-only first string fails; later fields do not hide it.
Non-string fields are skipped. A JSON string or non-empty plain text is also
accepted; JSON arrays, numbers, booleans, null and metadata-only objects are not
answers.

The default suite evaluator checks only HTTP success and a non-empty answer.
It does not evaluate RAG factual correctness, source recall, groundedness or
answer completeness. A successful default check must not be interpreted as
validation of those properties. Scripted workflow checks and
[semantic RAG evaluation](../rag-evaluation.md) are separate APIs.

Connector authentication can forward a bearer token or `X-API-Key`. Treat
connector credentials as secrets.

Private, loopback, link-local, and reserved targets are blocked by default.
Only set `HUMANLY_ALLOW_PRIVATE_CONNECTORS=true` for deliberate local testing.
Production deployments should also restrict outbound network access.

See the [setup guide](../guides/agent-connector-setup.mdx).
