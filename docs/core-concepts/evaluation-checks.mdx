# Evaluation checks

The default single-turn run path includes:

## `non_empty_response`

Passes when:

- The connector returns a successful HTTP status
- The response contains non-whitespace text in `response`, `message`, or
  `output`, or as a plain-text body

It fails with score 0 for non-success HTTP status codes, empty content,
unsupported JSON response shapes, timeouts, or unreachable agents.

## Workflow checks

The separate workflow runner supports scripted multi-turn L1–L5 evaluation in
both OSS and Studio: policy/action, bound approvals, state/target consistency,
structured outcome consistency, and progress/safe termination. It requires
runtime evidence and evaluator-side expectations. Missing evidence is
inconclusive and blocks the gate, not a pass.
See [workflow evaluation](../workflow-evaluation.md) for schemas, API, CLI and
provider-free faulty/fixed examples.

The wider Humanly Studio LLM evaluation catalog is not included in this release.
Additional deterministic OSS checks are on the
[roadmap](../ROADMAP.md).
