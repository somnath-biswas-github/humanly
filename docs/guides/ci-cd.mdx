# CI/CD quality gates

## Select the correct gate

For conversational, workflow and RAG runners, use the commands documented in
the [selection guide](../choose-your-test.md). Exit 0 means pass; both 1
(failure) and 2 (inconclusive/error) must block release. Model-based CI needs
provider credentials and may incur provider charges.

Conversation and RAG reports expose `qualityGate`; saved workflow CLI output wraps
the evaluator result under `report`, where `report.status` must equal `pass`.
The workflow HTTP API additionally supplies `qualityGate.passed`.
Use these gates rather than the legacy `baselineBreach` field.

The SDK/CLI examples below apply to **legacy single-turn suites**. A
non-empty-response baseline is a connectivity regression test, not evidence
of conversational or RAG quality. Its JSON reports contain `baselineBreach`.

## TypeScript SDK source

```bash
(cd packages/sdk && npm ci && npm run build && npm pack --pack-destination ../..)
npm install ./humanlyai-sdk-0.1.1-oss.0.tgz
```

The npm-published `@humanlyai/sdk@0.1.0` targets the hosted API. The local
prerelease above is the client verified against OSS v0.1.

```js
import { HumanlyClient } from "@humanlyai/sdk";

const humanly = new HumanlyClient({
  apiKey: process.env.HUMANLY_API_KEY,
  baseUrl: process.env.HUMANLY_BASE_URL
});

const run = await humanly.triggerRun({
  suiteId: process.env.HUMANLY_SUITE_ID,
  baselineId: process.env.HUMANLY_BASELINE_ID
});
const report = await humanly.waitForRun(run.id);

if (report.baselineBreach) process.exit(1);
```

## Repository CLI source

The CLI is not published in v0.1. Build the checked-out source:

```bash
npm --prefix packages/cli ci
npm --prefix packages/cli run build
node packages/cli/dist/index.cjs run \
  --suite "$HUMANLY_SUITE_ID" \
  --baseline "$HUMANLY_BASELINE_ID" \
  --out humanly-results
```

Store API keys in the CI provider’s secret store. Never commit them.
